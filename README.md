# SwipeTool · 屏幕滑动工具

一个轻量的 Android 手势工具：通过**无障碍服务**在屏幕上执行**方向、起点、长度、速度、轨迹、节奏**均可调的滑动操作。纯触摸事件模拟，不读取屏幕内容、不联网、不上传任何数据，也不针对任何具体 App。

![Build APK](https://github.com/ippceo/SwipeTool/actions/workflows/build.yml/badge.svg)
![Android](https://img.shields.io/badge/Android-7.0%2B-3DDC84)
![Version](https://img.shields.io/badge/version-1.8.1-blue)

> 适用场景：长页面自动滚动、阅读翻页、演示 / 手势测试等中性自动化辅助。
> 请勿用于绕过平台风控、刷量或任何违反第三方服务条款的用途（见文末免责声明）。

## 快速开始

1. **安装**：从 [Releases](https://github.com/ippceo/SwipeTool/releases) 下载最新的 `SwipeTool-<版本号>.apk` 安装（允许「未知来源安装」）。
2. **授权**：打开 App → 底部「执行」Tab → 点「开启无障碍权限」→ 在系统设置中打开「屏幕滑动工具」开关。
3. **设置参数**：底部「参数」Tab 调整起点、距离、时长等（每个分组都带快捷按钮），上方是按本机分辨率等比渲染的竖屏预览。
4. **开始**：在「执行」Tab 可设「启动延迟」（秒），点「开始滑动」会自动拉起悬浮球；趁延迟切到目标应用，滑动会在当前屏幕执行。停止时点悬浮球 / 通知栏，或回到 App 点「停止」。

## 界面（底部 Tab 分类）

| Tab | 内容 |
|---|---|
| **参数** | 每组参数有分隔线与快捷按钮、滑动预览（严格等比本机分辨率）、起点 / 距离 / 时长 / 间隔 / 弯曲 / 抖动等全部参数 |

内容按功能拆分到 4 个 Tab，单页不再过长；切换 Tab 时输入内容不会丢失。

## 功能特性

| 类别 | 说明 |
|---|---|
| 方向 / 角度 | 上下左右一键切换，也可填任意角度（0–359，支持斜向） |
| 起点 | 起点 X / Y 各支持「下限 ~ 上限」区间随机（屏宽 / 屏高百分比），相等即固定 |
| 长度 | 距离按**屏幕高度百分比**取值（0–100），支持「下限 ~ 上限」随机；按屏幕比例计算，不同手机体感一致 |
| 速度 | 滑动时长可在「时长下限 ~ 上限」之间随机，快慢更自然（两者相等即固定） |
| 轨迹 | 拟人化随机轨迹：起点、长度、方向与弯曲都可随机，轨迹带横向摆动 |
| 循环 / 往返 | 可设循环次数（0 = 无限）；往返可设回程停顿 |
| 节奏 | 两次滑动之间可设固定间隔；或开启「间隔随机」在最小~最大之间随机 |
| 随机抖动 | 0–100% 强度，越大越像真人：方向抖动、弯曲摆动、间隔扰动；连续操作不重复 |
| 启动延迟 | 主界面「开始 / 试放」可设 0–60 秒延迟，方便切到目标应用再开始；点悬浮球不延迟 |
| 录制序列 | 面板上手动画出多笔滑动并命名保存；可打开列表选择 / 删除 / 试放，回放保留真实抖动与弯曲 |
| 实时预览 | 严格按本机真实分辨率比例渲染的竖屏示意图，标出起点区间，抖动开启时画出多条随机轨迹 |
| 快捷按钮 | 起点（居中 / 顶部 / 底部 / 左 / 右）、方向、距离、速度、间隔、弯曲、循环、抖动均有快捷值 |
| 悬浮球 | 点「开始」自动拉起；浮在所有应用之上，点一下开始 / 停止，可拖动，靠近左右边缘松手会贴边半隐藏；运行中实时显示剩余 / 已完成次数 |
| 通知栏 | 可直接「开始 / 停止 / 退出」，点「退出」会直接关闭整个应用 |
| 参数提示 | 每个参数带取值范围，点右侧「!」查看详细含义 |
| 保存 / 另存 / 读取 | 「保存」让参数生效；「另存」写入 3 个槽位做模板；「读取」把槽位载入界面（再点保存才生效） |
| 时长上限 | 运行指定秒数后自动停止，避免忘记关 |

## 参数说明

| 参数 | 含义 | 范围 / 默认 |
|---|---|---|
| 起点 X 下限 / 上限 | 滑动起点横坐标的随机区间，按屏幕宽度百分比 | 0–100，默认 50 / 50（相等即固定） |
| 起点 Y 下限 / 上限 | 滑动起点纵坐标的随机区间，按屏幕高度百分比 | 0–100，默认 50 / 50（相等即固定） |
| 角度 | 0=右，90=下，180=左，270=上 | 0–359，默认 90 |
| 距离下限 / 上限 | 每次滑动长度的随机区间，按**屏幕高度百分比**（如 30 = 屏高 30%），相等即固定 | 0–100，默认 30 / 50 |
| 滑动时长 | 单次手势持续（ms），越小越快；在「下限 ~ 上限」之间随机 | 50–60000，默认 400 / 700 |
| 间隔 | 两次滑动之间等待（ms，未开启间隔随机时生效） | 0–600000，默认 500 |
| 最小间隔 | 开启「间隔随机」后，间隔下限（ms） | 0–600000，默认 200 |
| 最大间隔 | 开启「间隔随机」后，间隔上限（ms），每次循环在此区间随机 | 0–600000，默认 800 |
| 循环次数 | 0 表示无限 | 0–1000000，默认 0 |
| 往返停顿 | 回程前停顿（ms） | 0–60000，默认 200 |
| 弯曲幅度 | 轨迹的基础弧度，单位为屏幕高度百分比，0 为直线，正负向两侧弯 | -100–100，默认 0 |
| 运行时长上限 | 到达后自动停止（秒） | 0 = 不限，最大 86400 |
| 随机抖动 | 拟人化随机强度（%），影响方向 / 弯曲 / 摆动与间隔 | 0–100，默认 40 |
| 启动延迟 | 点「开始 / 试放」后等待的秒数，方便切到目标应用 | 0–60，默认 0 |

> 从旧版本升级时：原来的单值起点会迁移为「下限 = 上限 = 原值」；原来以 dp 存的距离会按当前屏幕高度换算成百分比，滑动长度体感与原来接近。

## 「保存」与「另存到槽位」的区别

两者作用不同，因此不合并：

- **保存当前参数**：把界面参数写成「生效配置」，**悬浮球和下次启动都会用它**（立即生效）。
- **另存到槽位**：仅存成模板（共 3 个槽），**不会自动生效**；需要「读取槽位」载入界面后再点「保存」才生效。

简单说：保存 = 立即生效；另存 = 存档备用。

## 拟人化随机轨迹与随机间隔

### 拟人化随机轨迹

强度 `jitter = jitterPercent / 100`，每次滑动都会重新随机：

| 维度 | 随机方式 |
|---|---|
| 起点 X / Y | 在「下限 ~ 上限」区间内随机取值；再叠加 ±`j × 6%` 屏幕短边的微偏移 |
| 长度 | 在「距离下限 ~ 距离上限」（屏高百分比）之间均匀随机 |
| 方向角 | ±`j × 22°` |
| 弯曲 | 在基础弯曲上再叠加 ±`j × 8%` 屏幕高度的随机偏转 |
| 轨迹摆动 | 路径分成 5~8 段，沿垂直方向叠加随机摆动（约路径长度的 `j × 6%`） |

例如抖动设为 `40`，方向 ±8.8°、弯曲 ±3.2% 屏高，轨迹本身也会歪歪扭扭。设为 `0` 时关闭方向 / 弯曲 / 摆动随机，但起点与长度仍会在各自「下限 ~ 上限」内随机；把上下限填成同一个值即可完全固定。

### 随机间隔

开启「间隔随机」后，每次循环的间隔会在「最小间隔 ~ 最大间隔」之间随机取值，可再叠加「随机抖动」的间隔扰动。

## 使用

### 方式一：在 App 内操作

1. 打开 App，在「执行」Tab 完成无障碍授权（见「快速开始」）。
2. 在「参数」Tab 设置参数，点「开始滑动」（直接使用界面上的当前参数，不会自动保存）。
3. 切到任意界面，滑动会在当前屏幕上执行。
4. 停止：点悬浮球、通知栏「停止」，或回到 App 点「停止」。
5. 想让悬浮球或下次启动也使用这套参数：在「预设」Tab 点「保存当前参数」；只想存成模板则点「另存到槽位」，以后用「读取槽位」载入。
6. 想回放真人轨迹：在「录制」Tab 录制并保存，勾选「使用录制序列回放」后再点「保存」。之后点「开始滑动」或悬浮球都会回放该序列；「试放一次」可立即验证。

### 方式二：悬浮球（跨应用快速启停）

1. 先在 App 内设置参数并点「保存当前参数」。
2. 点「开始滑动」会自动拉起悬浮球；也可在「执行」Tab 手动点「开启悬浮球」，按提示允许「显示在其他应用上层」（Android 13+ 还会请求通知权限）。
3. 屏幕边缘出现圆形悬浮球（灰蓝 ▶ = 停止，绿色 ■ = 运行中）。运行中球底部角标会显示次数：有限循环显示剩余次数，无限循环显示已完成次数。
4. 切到任意应用，点悬浮球即可开始 / 停止；按住拖动可调整位置。悬浮球始终使用「已保存」的参数，界面上未保存的修改不会生效；点悬浮球不经过「启动延迟」。
5. 退出：下拉通知栏，点通知里的「退出」，会停止滑动并**直接关闭整个应用**；通知内也可直接「开始 / 停止」。

## 工作原理

核心是 Android 标准的 `AccessibilityService` + `GestureDescription`：

1. `SwipeAccessibilityService` 注册为无障碍服务，获得发送手势的能力（`canPerformGestures`）。
2. 根据参数计算起点（在 X / Y 区间内随机）与终点坐标（长度在区间内随机、方向 / 弯曲带抖动），构造 `Path`（多段三次贝塞尔，并叠加横向摆动）。
3. 用 `GestureDescription.Builder` 添加 `StrokeDescription`，通过 `dispatchGesture` 交给系统执行。
4. 用 `Handler` 按「手势时长 + 间隔」循环调度，实现连续 / 往返滑动。
5. 启用录制序列时，`RecordedSequence` 中每一笔的归一化采样点（0~1）映射到当前屏幕，按录制时的启动时间与持续时间重建 `StrokeDescription`；超过系统单次 10 笔的限制时自动按时间分批发送。录制数据仅保存在本机 `filesDir/recordings.json`。

全程只发送标准的触摸事件序列，没有任何平台识别或对抗逻辑。

## 常见问题（FAQ）

**Q：无障碍服务开了但状态显示「服务未连接」？**
A：先确认系统设置里「屏幕滑动工具」开关已打开；部分系统开启后需要稍等或重启 App。若仍不行，可开关一次或重启设备。

**Q：悬浮球不显示？**
A：需要授予「显示在其他应用上层」权限；MIUI / ColorOS 等系统还需在「后台弹出界面」「自启动」等设置中放行本应用。

**Q：切到其他 App 后无法从本 App 停止？**
A：这是预期行为——滑动在当前前台屏幕执行。请使用悬浮球、通知栏「停止」，或回到 App 停止。点「开始」时已自动拉起悬浮球，方便跨应用停止。

**Q：连续滑动轨迹太固定 / 想更随机？**
A：把「随机抖动」调到 30–60，再把「距离下限 / 上限」「起点 X / Y 上下限」拉开一点；抖动为 0 且上下限相同时才会完全固定。

**Q：距离原来的 dp 值怎么换算？**
A：新版本距离按屏高百分比计算，1.8.0 升级会自动把旧 dp 值按当前屏幕高度换算成百分比；1.8.1 起弯曲幅度也改为屏高百分比。常见参考：屏高约 800dp 时，300dp ≈ 37%，500dp ≈ 62%。

## 云端构建（无需本地环境）

本项目通过 GitHub Actions 在云端编译，本地**不需要**安装 Android Studio / JDK / Gradle。

- 工作流：`.github/workflows/build.yml`
- 触发：向 `master` / `main` 分支 push，推送 `v*` tag，或在 Actions 页面手动 `Run workflow`
- 产物：Actions artifact 为 `SwipeTool-<版本号>-debug.apk` 与 `SwipeTool-<版本号>.apk`
- 发布：**推送 `v*` tag** 时自动创建 GitHub Release，附件名为 `SwipeTool-<版本号>.apk`
- 签名：release 使用固定签名密钥。CI 通过 GitHub Secrets（`KEYSTORE_BASE64` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`）注入；未配置时回退 debug 签名（版本间签名会不一致，仅供本地调试）
- 混淆：release 开启 R8 代码混淆 + 资源压缩，减小 APK 体积
- 环境：JDK 17 + 预装 Android SDK（`platforms;android-34`、`build-tools;34.0.0`）+ Gradle 8.7；依赖走阿里云 Maven 镜像，避免 Maven Central 限流

## 已知限制

- 滑动在当前前台屏幕上执行；切到其他 App 后无法从本 App 界面直接停止，需回到 App，或用悬浮球 / 通知（点「开始」已自动拉起悬浮球）。
- 部分厂商系统（MIUI / ColorOS 等）对无障碍服务有额外限制，若被自动关闭需在系统设置里加入白名单。
- 坐标系为物理屏幕像素，起点与终点会自动裁剪到屏幕范围内。
- 录制序列单段最多 20 笔、60 秒，单笔最多 3000 个采样点。
- 悬浮球需授予「显示在其他应用上层」权限；部分系统（MIUI / ColorOS 等）还需在「后台弹出界面」等设置中放行，否则可能不显示。
